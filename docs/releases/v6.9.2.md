# ChatISA v6.9.2 Release Notes

**Release Date:** September 25, 2026

---

## Overview

Housekeeping and the loose ends from v6.8.0 and v6.9.0:

- files stored with Git LFS now import properly;
- repositories whose default branch name contains a slash now read;
- the next-term prompt no longer clears work in progress;
- the syllabus refresh runs one week into each term;
- the retired Streamlit app leaves the main branch.

## What students get

- **Git LFS files import with their real content.** GitHub stores a large
  file tracked by [Git LFS](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md)
  as a small pointer. Import from GitHub used to bring in that pointer
  text instead of the file.
  - It now follows the pointer to GitHub's LFS host and imports the real
    file.
  - A file over 25 MB is refused before it is downloaded, with the same
    reason as any other file over the limit.
  - If GitHub will not serve the file (for example, the owner's LFS
    bandwidth is used up), the file is named and stays ticked, so it can
    be tried again.
  - The student's GitHub token is never sent to the LFS host. Only public
    repositories are listed, so the token is not needed there.
- **Job Scout's "Your GitHub" skips LFS pointers**, since a pointer says
  nothing about the student's code.
- **Default branches with a slash** (for example `release/2026`) now read
  in both Job Scout and the Portfolio Builder. The file list is read from
  the repository's default branch by reference, not by name.
- **The next-term prompt keeps work in progress.** Answering "Finished" or
  "Still taking" used to reset the My Profile tab, which cleared
  unconfirmed resume suggestions and typed text. The tab now takes the
  updated courses and keeps everything else.

## Syllabus refresh schedule (professor, 2026-09-24)

The catalog refresh Action now runs one week into each term instead of on
Feb 1, Jun 1 and Sep 1.

- **Fall, Spring and Summer:** the Monday one week after classes start.
  Classes start on a Monday between the 22nd and the 28th, so the Action
  wakes daily from the 29th to the 4th and runs only on that window's one
  Monday. Examples:
  - Fall 2026 classes began Aug 24 (run: Aug 31);
  - Spring 2027 begins Jan 25 (run: Feb 1);
  - Summer 2027 main sessions begin May 24 (run: May 31).

  Sources:
  [2026-2027 calendar](https://miamioh.edu/academic-programs/academic-calendar/2026-2027.html),
  [2027-2028 calendar](https://miamioh.edu/academic-programs/academic-calendar/future-calendars/2027-2028.html).
- **Winter term** (Jan 2 to 22, 2027): runs on Jan 9.
- **Each window runs once.** A second run before the first pull request is
  merged would map the same courses again and open a duplicate pull
  request (review fix).
- **Scope caveat:** the rule assumes the Monday start pattern holds. Summer
  2028's term is listed as beginning May 15, so that summer's run would
  land two weeks in. A manual run from the Actions tab is always
  available.
- **Actions updated:** `actions/checkout` and `actions/setup-node` move to
  v7. GitHub removed Node 20 from its runners on September 23, 2026
  ([GitHub changelog](https://github.blog/changelog/2025-09-19-deprecation-of-node-20-on-github-actions-runners/)).
  The workflow runs on `ubuntu-latest` and needs only bash, git, the `gh`
  CLI and the Node version `setup-node` installs. No change is expected
  when the runner image moves to a newer Ubuntu.
