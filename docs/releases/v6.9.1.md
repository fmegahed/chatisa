# ChatISA v6.9.1 Release Notes

**Release Date:** September 25, 2026

---

## Overview

A security release. It updates Next.js and Auth.js past critical
advisories, and patches every other flagged dependency. Deploy it
promptly; it also carries v6.7.0 through v6.9.0 if those are not deployed
yet.

## Security fixes

- **Next.js 16.2.10 to 16.3.6.** Fixes two critical advisories:
  - "Unauthenticated Remote Code Execution on windows-hosted servers" (the
    production server runs Windows);
  - "Unauthenticated Remote Code Execution in Image Optimization API when
    AVIF files are used".

  Also fixes several high-severity Next.js advisories.
- **next-auth 5.0.0-beta.31 to beta.32, and @auth/core 0.41.3.** Fixes:
  - "Email normalizer validates the address before Unicode normalization,
    allowing a homoglyph @ bypass";
  - "Configuration errors can cause existence-based auth checks to fail
    open".

  ChatISA's Miami-only rule is its own server-side domain check behind
  Google sign-in, but the library is patched regardless.
- **Other packages:** sharp 0.35.4, postcss 8.5.23, nanoid 3.3.19. The
  development-only tools (js-yaml, browserslist, brace-expansion, Vitest,
  and the old esbuild loader behind drizzle-kit) are pinned through npm
  overrides.
- **Result:** `npm audit` reports 0 vulnerabilities, development tools
  included.

## Other changes

- **The GitHub connect page reads its result once.** Next.js 16.3 surfaced
  a development-only double run that replaced "This connection attempt
  could not be verified" with a generic message. Production was not
  affected; the page is now robust either way.
- **Lint:**
  - Next.js 16.3's new rule against `window.location.assign` is marked as
    a documented false positive for the OAuth start route, which must be a
    full page load;
  - two lint warnings in the tag evaluation script are fixed.

- **Coding Studio keeps text typed while the editor loads.** Until the
  full code editor arrives, a plain text box stands in. Text typed there
  was replaced by the starter script when the editor finished loading,
  because the editor started from the text as it was when loading began.
  It now starts from what the student typed. Found through an end-to-end
  test that failed on a cold development server; a slow connection could
  cause the same thing in production.

## Operator notes

- Copy `web/deploy/chatisa-app.zip` to the server as usual (it is a tar;
  extract with 7-Zip or `tar -xf`). No configuration changes.
- The bundle carries the patched versions: Next.js 16.3.6 and sharp 0.35.4
  are in its `node_modules`, and the auth libraries are compiled from the
  patched lockfile. It booted and passed its self-test (PDF worker,
  database write and read, brand assets) before it was packed.

## Test and gate results

- Type check and lint clean.
- Unit: 1,146 of 1,147 pass. The one failure is the known speech-probe
  timeout under full-suite load, which passes alone.
- End to end on Next.js 16.3.6: every group passes at desktop and 320 px,
  run group by group. Two tests needed attention:
  - "Clear empties SQL console output" failed on a cold development
    server. Its trace led to the Coding Studio fix above, and the test now
    confirms its script is in the editor before running it (the editor can
    be rebuilt just after the first click on a cold server). It passes at
    both widths, including a run on a cold server.
  - "statsforecast fits real models" timed out once under load (a
    3.6-minute run of our own wasm build) and passed when run alone.
- The shared sign-in setup's Coding Tutor warm-up now has time limits like
  the other warm-ups; without them it twice waited out the whole
  10-minute setup budget on Next.js 16.3.
