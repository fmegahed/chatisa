# ChatISA v6.11.0 Release Notes

**Release Date:** November 17, 2026

---

## Overview

Plots can now be explored from the keyboard and heard (issue #40, the
follow-up to the September 2026 accessibility audit). Tab to a plot and the
arrow keys move from value to value, each one announced ("Course is ISA 401,
Average grade is 3.2"); S plays the values as tones, T changes how much text is
read, B shows braille, and Ctrl+/ lists every key. This works for Python
(matplotlib, seaborn, pandas), R (ggplot2) and SQL (ggsql) plots, wherever a
plot appears: the Coding Studio's Plots pane, runnable code in Coding Tutor,
Ask Anything, AI Comparison, Project Assistant and Sandbox chat replies, and
Ask Anything's tool cards. The audit recommended MAIDR (maidr.ai), which was
built and evaluated with blind users (CHI 2024); ChatISA now uses it.

## What students get

- **Six chart types:** bar (including grouped and stacked), histogram, line
  (several series), scatter, box plot and heatmap.
- **Each value announced** through a screen reader, with the axis names:
  "Course is ISA 401, Average grade is 3.2". Colour groups are named after
  the legend: "Student is Amanda, Grade is 91, Course is ISA 401".
- **Sound, text and braille:** S, T and B, as in MAIDR's published study.
- **No change for anyone not exploring by keyboard.** A plot looks and
  behaves as before for a student who uses the mouse: clicking or tapping it
  focuses nothing (dragging and right-click save work as before), so MAIDR
  stays asleep and the arrow keys never play tones. The hint ("Explore this
  chart from the keyboard...") is read by screen readers and appears on screen
  only while the chart has keyboard focus. The one difference for a sighted
  keyboard user is a Tab stop on each explorable plot, which is also how
  screen reader users reach it (a browser cannot tell whether a screen reader
  is running).
- **A "Plots" group** in the Coding Studio's keyboard shortcuts.
- **Unchanged for everything else:** charts MAIDR cannot navigate here
  (several panels or facets, base R graphics, pie charts) keep the picture
  and the description from v6.10.0 (#23). Very large plots are sampled to at
  most 1,000 points per scatter layer or 2,000 per line, and the hint says so
  (when the chart has keyboard focus).
- **R plots get real descriptions too.** v6.10.0 could describe R plots only
  from the code; ggplot's title, axis labels, chart type and legend now come
  from the plot itself.

## How it works

- Nothing new is installed in the in-browser runtimes. ChatISA reads the data
  it already has: the Python worker reads the matplotlib figure it saves, the R
  worker reads the drawn ggplot with `ggplot_build()`, and SQL plots read the
  Vega-Lite spec ggsql produces.
- `lib/run/maidr-schema.ts` validates that data and builds MAIDR's JSON field
  by field. maidr.js runs one schema field (an axis format function) as code,
  so the builder never emits it, whatever a plot's code produced.
- `components/run/AccessiblePlot.tsx` puts the JSON on the plot's image and
  loads maidr.js once per page. MAIDR's own language follows the browser; it is
  set to English to match the page, and a student can change it in MAIDR's
  settings (Ctrl+,).

## Licence and third-party code

maidr.js is GPL-3.0-or-later; ChatISA stays MIT. By the professor's decision,
MAIDR ships as a **separate, unmodified file**, served from ChatISA's own
origin and loaded at runtime, never compiled into ChatISA's code:

- Pinned to MAIDR **4.16.0** (released October 19, 2026).
  `npm run setup:runtimes` checks the npm package's published sha512 and
  maidr.js's sha256 against `web/lib/run/maidr-pin.json`, and the deploy
  bundle refuses to build without the verified file, its licence and notice.
- `THIRD_PARTY_NOTICES.md` (new) records the version, licence, integrity and
  the source at the exact commit. The Coding Studio's runtime notes link the
  licence and the source.
- A unit test fails if any ChatISA file imports `maidr` or if it becomes an npm
  dependency.
- No request leaves ChatISA's origin by default (checked in the e2e tests).
  MAIDR's optional AI chat stays off unless a student enters their own API key
  in MAIDR's settings; a DotPad tactile display loads its SDK from jsDelivr
  only when one is used.

## Tests

- New unit tests: the MAIDR schema builder (every chart type, sampling, and a
  deep check that no executable field is ever emitted), SQL plot data read
  from the live ggsql-wasm (so a ggsql upgrade that changes its spec fails
  loudly), and the licence boundary.
- New e2e tests (`tests/e2e/plots-maidr.spec.ts`), at desktop and 320 px:
  Python, R and SQL plots in the Coding Studio announce their first values;
  runnable code in a Coding Tutor reply and an Ask Anything tool call do too;
  no third-party request; MAIDR's keys never reach the editor; paging between
  plots leaves exactly one chart; the Coding Studio with a plot on screen is
  axe-clean with no stray tab stops.
- The Python and R extraction was also checked outside the browser against
  matplotlib 3.11 and ggplot2 4.0.3 for each chart type.

## Known limits

- Not yet tested with real screen readers (NVDA, JAWS, VoiceOver). MAIDR
  switches the focused chart to role="application", which screen readers
  normally treat as "pass the keys through", but that needs a person to
  confirm. Worth including in the accessibility office's planned pass.
- PNG plots have no visual highlight of the current value (the picture is a
  bitmap); sound, text and braille all work.
- A chart whose legend has no title (pandas' grouped bars, for example) still
  calls its colour groups "Level", MAIDR's default name.
- Keyboard only by design: a mouse click does not wake a chart. Screen reader
  users reach it with Tab. A screen reader that activates by simulating a real
  mouse click (rather than its usual synthetic click) would not wake it either;
  worth including in the accessibility office's pass (JAWS virtual cursor,
  Enter on the chart).
- On a navigable chart, a screen reader hears MAIDR's short name ("ISA grades
  by student and course, Dodged Bar Chart") rather than the longer
  description, which stays one Tab away under "Describe this plot".
- Multi-panel figures, facets, base R graphics and lattice are described but
  not navigable in this release.

## Operator notes

- Run `npm run setup:runtimes` (or just `node scripts/setup-runtimes.mjs
  maidr`) on the build machine before building the bundle; the bundle check
  stops if MAIDR is missing.
- No configuration changes.

## Hands-on check in Chrome (November 17)

The Coding Studio's own examples, tried by keyboard in a real Chrome against
a test-mode dev server, found two problems the automated tests had missed;
both are fixed and now covered by an e2e test:

- **The plot was clipped in the Plots pane.** MAIDR wraps the image in its
  own article, figure and div, and the image no longer shrank to the pane
  (429px of plot in a 242px pane, top and bottom cut off). Those wrappers now
  pass the pane's size down (`globals.css`); chat replies and tool cards, which
  have no fixed height, are unchanged.
- **The Python example read "Student is 0, Group is Series 1".** matplotlib
  stores names plotted on an axis as positions; the extraction now reads them
  back from the axis, skips lines that run along a category axis (the
  dumbbell's connectors), and reads dots on one category axis as bars, as the
  R and SQL extraction already did. A line over month names now reads "Jan",
  not 0. The other chart types give the same data as before (checked locally
  against matplotlib 3.11).

After the fix, the Python and R examples both read "Student is Amanda, Grade
is 91, Level is ISA 401", and ArrowUp switches course ("Student is Bill, Grade
is 79, Level is ISA 444"). "Level" is MAIDR's default name for colour groups;
ChatISA now passes the legend's title instead (`axes.z.label`; the matplotlib
legend or colour bar, the ggplot fill or colour label, the ggsql fill or
stroke title), so all three examples read "..., Course is ISA 401", and a
heatmap names its values ("Grade is 90"). Tab reaches the chart, the focus ring shows, and T
(terse text: "Bill, 88, ISA 401"), B (braille field) and S (sound on/off) all
work.

Re-run after the fixes: type check and lint clean; the 28 MAIDR unit tests
pass; `plots-maidr`, `sandbox` and `chart-examples` e2e: 103 passed, 22
skipped (opt-in live tests), none failed, at desktop and 320 px, including the
new "Python example reads student names and fits the pane" test.

After the legend-title wording: type check and lint clean; unit 128 files,
1,225 tests pass; `plots-maidr` e2e 7 of 7 at both sizes, now also checking

Keyboard only (no change for mouse users), checked in Chrome: a click on the

## e2e: the sign-in reload loop

The first e2e run after a batch of source edits used to loop on `/login`
until the 10-minute timeout (five times on November 17, including the
v6.10.1 merge run). Captured hot-reload messages showed the cause: the dev
server's restored on-disk Turbopack cache kept sending "restart" for a stale
entry chunk list. The e2e server now runs without that cache
(`CHATISA_E2E_NO_DEV_CACHE`, read in `next.config.ts`); everyday `next dev`
keeps it. `auth.setup.ts` also fails within seconds if a loop ever comes
back. The dev server's `EPERM` rename failures in `.next` point at Dropbox
locking files there; excluding `web/.next` from Dropbox is the suggested
follow-up.
