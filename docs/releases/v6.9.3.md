# ChatISA v6.9.3 Release Notes

**Release Date:** September 28, 2026

---

## Overview

The weekly job harvest had two faults. The employer-postings source had
been failing for weeks under a misleading label, and this Sunday's run
stalled and would have blocked every later one. This release fixes the
stall, records the real reason when a source fails, and corrects two
lines of outdated Job Scout copy. It is paired with a configuration
change on the server: the RapidAPI key. See the operator notes.

## What was wrong (from the production `scout.db`)

- **Employer postings stopped after August 23.** Active Jobs, the source
  of postings from employers' own hiring pages, was refused every week
  from at least September 6, and partway through on August 23. The run
  log said "429 (plan quota exhausted)". But the account's PRO
  subscription (5,000 jobs a month) showed 0% used: the key in use was
  not the one on the subscribed plan. Since August 23 the board has held
  only USAJobs postings (365 this week).
- **The September 27 harvest never finished.** It stored this week's
  postings until 06:55 UTC, then waited forever on one tagging request
  that never answered. The scheduler books its next check only after a
  run ends, so no harvest would run again until the service restarted.

## Fixes

- **Tagging has a time limit.** Each posting's model call gets two
  minutes. A call past the limit is cancelled and counted as one failed
  posting, and the run finishes. The job sources already had limits;
  tagging was the one step without one.
- **The real reason is recorded.** When Active Jobs refuses a request
  (429, 401 or 403), the run log keeps RapidAPI's own message, for
  example "You are not subscribed to this API", instead of always saying
  "quota exhausted". The harvest still stops calling the source for the
  rest of that run, because every further query would fail the same way.
- **Job Scout copy.** The introduction and the empty board said "the ISA
  courses you have taken". That has been out of date since v6.7.0, when
  the checklist grew to cover every FSB program. Both now say "the
  courses you have taken".

## Operator notes

- **Server configuration (required):** set `RAPIDAPI_KEY` in the
  server's environment to the key of the RapidAPI app on the subscribed
  PRO plan. The same key was checked on September 28: it returned 200
  with a limit of 5,000 jobs and 2,500 requests a month. The harvest
  budget is at most 1,100 jobs a week, about 4,700 a month, which fits.
- Copy `web/deploy/chatisa-app.zip` to the server as usual, then
  restart. The restart also ends the stalled harvest. Within the hour
  the scheduler sees no successful run since the September 27 boundary
  and harvests again, this time from both sources.
- The September 27 row stays marked "running" in `scout_runs`. It no
  longer blocks anything, because runs older than two hours are ignored.

## Test and gate results

- Type check and lint clean.
- New unit tests, each seen failing first:
  - a tagging call that never answers (it hung before the fix);
  - RapidAPI's message kept for a 429 and for a 403.
- Unit: the harvest and source suites pass. In the full suite, the
  health and speech-probe tests timed out under load. They call a live
  provider, and they pass on their own.
- End to end: Job Scout and the course checklist pass at desktop and
  320 px.
