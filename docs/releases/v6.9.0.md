# ChatISA v6.9.0 Release Notes

**Release Date:** September 24, 2026

---

## Overview

The Portfolio Builder can now start a career project or a showcase from
one of the student's own public GitHub repositories. The student picks the
repository, ticks its files, and they arrive exactly as if uploaded; the
page links back to the repository, which is only read and never changed.
This is part B of the professor-approved design
(`docs/superpowers/specs/2026-09-24-github-reading-design.md`); part A,
skills from repositories in Job Scout, shipped as v6.8.0.

## What students get

- **"Import from GitHub"** in the career Projects step (one per project)
  and the showcase Files step, beside "Add files". It opens inline, not as
  a pop-up.
- **Their own public repositories**, then the chosen repository's files
  with sizes and roles. Generated and hidden folders are left out. The
  README and the main code and notebooks are pre-ticked, up to the room
  left in the project; data files are never pre-ticked, since they may be
  licensed.
- **Files arrive like uploads**, so roles, the size meter, notebooks (plots
  kept for publishing) and publishing all work as before. Two files with
  the same name, or a name already in the project, arrive under
  distinguishable names.
- **Links back.** A career project's title and link fill in from the
  repository when empty. A showcase shows "Original repository" on its
  page, and only a real `https://github.com/owner/repo` address is ever
  shown.
- **Careful with the student's time:**
  - edits made while files download are kept;
  - a file that fails to download is named, and the rest still import;
  - reopening the panel never imports the same files twice;
  - the repository choice is locked while a file list loads;
  - an expired connection offers Connect GitHub again.

## One file size rule (professor, 2026-09-24)

- **A file over 25 MB cannot be added,** by upload or by import, and the
  student is told why ("over the 25 MB limit for one file on a published
  page"). The builder publishes from the browser, and 25 MB is the most it
  sends for one file. This used to accept such files as "too large to
  publish".
- **The same for every model.** No model receives a file's bytes: text
  files give their first 30,000 characters and other files only their name
  and size. The largest prompt (about 45,000 tokens) fits the smallest
  context window offered in the Portfolio Builder (131,072 tokens).
- **One size unit everywhere:** binary megabytes with one decimal, so a
  file under the limit never reads as over it.

## Privacy

- The GitHub token stays in the browser. Repositories are read directly
  from GitHub; our server never sees the token or the repository.
- Nothing is written to the source repository.

## Operator notes

- Copy `web/deploy/chatisa-app.zip` to the server as usual (it is a tar;
  extract with 7-Zip or `tar -xf`). No server configuration changes.

## Test and gate results

- **Unit:** 1,145 of 1,147 pass. The two failures are the known
  speech-probe and editor-indent timeouts under full-suite load; both pass
  alone. New tests, each written failing first, cover:
  - which files are offered, pre-ticked and refused;
  - names, including clashes with existing files;
  - repository link validation;
  - reading the file list and raw files;
  - the 25 MB rule for uploads;
  - the size formatter;
  - the "Original repository" link on the page.
- **End to end:** the Portfolio Builder, Job Scout and job search specs
  pass at desktop and 320 px (55 of 55 each), including the new Import
  from GitHub spec. It covers:
  - career and showcase imports;
  - a failed download;
  - an expired connection;
  - edits during a slow import;
  - no re-imports;
  - the repository lock;
  - the 25 MB upload refusal;
  - axe A/AA with no sideways scroll.

  The rest of the suite passed in full for v6.8.0 earlier today; this
  release changes only Portfolio Builder and GitHub-reading code.
- **Live check:** a real import from the professor's public
  `fmegahed/chatsqc` into a career project brought in 10 files and set
  the link; no request to our server carried the token.
- **Independent review** confirmed the hard rules: the token stays in the
  browser, source repositories are only read, and page links are
  validated. It found seven issues, all fixed:
  - edits lost during downloads;
  - the file room not enforced, with duplicate re-imports;
  - name clashes with existing files;
  - a repository-switch race;
  - an unannounced confirmation;
  - two size units;
  - an unvalidated link in the builder.
- **Recorded decision:** files stored with Git LFS would import as their
  small pointer text. This is rare in student repositories, and the
  student can remove such a file.
