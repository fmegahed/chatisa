# ChatISA v6.3.0 Release Notes

**Release Date:** August 20, 2026

---

## Overview

A full model-catalog refresh (ADR-005, ADR-018). Every route below was
verified live on 2026-08-20: `scripts/check-proposed.ts` against each
provider's own listing, then `npm run verify:models` calling all 21
catalog models for real (21/21 chat pass; structured output pass on every
route that claims it). Vision routes new to this release were additionally
probed with a real image. Every price in the catalog was re-read from the
provider's published rate the same day.

- **Qwen3.8 27B replaces Qwen3.6 35B.** Served by exactly one router

## GitHub auto-push and the Portfolio Site tab

Job Scout's projects no longer end at a zip file and a list of CLI
commands. With a GitHub OAuth App configured on the server
(`GITHUB_OAUTH_CLIENT_ID`/`SECRET`, optional), students get:

- **Connect GitHub once** (popup OAuth, `public_repo` scope only, so the
  token cannot see private repositories). The token lives in the
  student's browser, never in a ChatISA table or log; the server's only
  role is the code-for-token exchange. Disconnect is one click, with a
  pointer to full revocation on github.com.
- **One-click push** for both scaffolded and polished projects: the repo
  is created public, files are committed through GitHub's git data API
  (one tree, one commit), and the project card flips to "Built" with its
  skills counting in the profile automatically. A same-named repo the app
  did not create is never overwritten; the student is offered a suffixed
  name instead. The CLI instructions survive behind "Prefer the command
  line?". Push is offered only while a project is unlinked, so a repo the
  student has since built out cannot be clobbered by re-pushing stubs.
- **A new Portfolio Site tab**: pick up to 5 saved jobs, and an LLM
  merges the device resume, profile, and built projects into a
  self-contained one-page site written to speak to that whole range of
  jobs, with private per-job notes explaining the emphasis. One click
  publishes it to a `portfolio` repo with GitHub Pages; retailoring
  republishes the same repo. The model produces content JSON only; a
  deterministic, fully escaping template renders the page, so employer
  job text can never inject markup into a site published under a
  student's name.

The starting point was the CareerBridge prototype's GitHub service,
improved substantially: OAuth state is actually validated (login-CSRF),
tokens are never stored server-side (CareerBridge kept them plaintext in
a database), the scope shrank from `repo,user` to `public_repo`, the
fixed 2-second repo-creation sleep became ref polling, and per-file blob
round-trips became a single tree request.

Operational notes: absent OAuth env pair hides the feature and keeps the
manual flow; GitHub Pages enablement via API may require broader scope
than `public_repo` on some accounts, so a failed enable falls back to a
one-click link to the repo's Pages settings. The scout project rate limit
became env-overridable (`CHATISA_SCOUT_PROJECT_LIMIT_PER_MINUTE`, default
4) like every other limit.

## statsforecast in the browser (own wasm build)

The Coding Studio's canonical "cannot install here" example is now
pre-installed. statsforecast 2.x dropped numba but moved its kernels into
compiled C++ (in itself and in coreforecast), and neither PyPI nor Pyodide
ships a WebAssembly build, so we cross-compiled both for this app's exact
Pyodide ABI (`scripts/build-wasm-wheels.sh`, Docker + pyodide-build; the
one required fix was forcing pybind11's modern FindPython, since
coreforecast sets a variable pybind11 does not read). The wheels live in
`vendor/pyodide-wasm-wheels/` and are ABI-checked at setup time, so a
future Pyodide upgrade fails the build loudly instead of serving a wheel
that cannot load.

The support cast rides along as ordinary pure-Python hosted wheels:
utilsforecast, plus fugue with triad and adagio, because
statsforecast.core imports fugue unconditionally even though only its
cluster backends would ever use it. Their `pandas<3` pins are metadata
only; the full stack was verified live against Pyodide's pandas 3.x.

Measured in the real runtime: AutoARIMA + AutoETS + Naive fit and
forecast 60 monthly observations in 1.2 seconds. `import statsforecast`
now classifies as "ready" in the package checker and the Run-button gate;
pyreadr inherits the role of the canonical impossible package across the
help copy, the mock model, and the gate tests. A new sandbox e2e runs an
actual AutoETS fit end to end through the Coding Studio UI. Added
mirrored lock packages for offline installs: cloudpickle, tqdm,
threadpoolctl, narwhals, packaging, six, fsspec (~1 MB total; the whole
forecast stack adds about 1.4 MB to the runtime assets).

## Route-audit hardening

`scripts/check-proposed.ts` now falls back to the router's per-model
endpoint before declaring a model unserved: the bulk `/v1/models` listing
omits some models the router does serve (observed with Qwen3.8-27B), and
a discovery tool that quietly under-reports is worse than none.

## Test and gate results

- `check-proposed`: all routes served and price-matched; the only flag is
  Ternary Bonsai's known lack of structured output, which the catalog
  already records.
- `verify:models`: 21/21 chat pass, structured output pass everywhere it
  is claimed, $0.02 total probe cost.
- 856 unit tests (18 new for the GitHub push path, the OAuth state
  helpers, and the portfolio renderer's escaping): 854 passed; the two
  failures are the known health-route 5-second timeouts under full-suite
  parallel load, passing 14/14 in isolation, unrelated to this change.
- Job Scout e2e: 23/23 on desktop and mobile-320, including the popup
  OAuth connect (against the mock GitHub server mode), a one-click
  scaffold push against an intercepted fake api.github.com, a forged
  OAuth callback being rejected, portfolio generation plus Pages publish,
  and an axe WCAG A/AA scan of the new tab. No test traffic touches the
  real GitHub.
- Typecheck and lint clean.
