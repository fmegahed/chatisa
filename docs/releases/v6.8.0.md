# ChatISA v6.8.0 Release Notes

**Release Date:** September 24, 2026

---

## Overview

Job Scout can now suggest skills from a student's own public GitHub
repositories. The student picks up to five, reads the suggestions with the
reason for each starting level, and confirms each skill at any level. This
helps most for guests, who have no Miami courses, and for any student
whose best evidence is code they wrote outside class.

This is part A of the professor-approved design
(`docs/superpowers/specs/2026-09-24-github-reading-design.md`). Part B,
importing a repository into the Portfolio Builder, is planned for v6.9.0.

## What students get

- **A "Your GitHub (optional)" block in My Profile,** below the resume
  section. It uses the GitHub connection students already have (Connect
  GitHub, public repositories only).
- **Their own repositories to pick from:** public, owned by them, forks and
  archived repositories left out, most recently updated first, with a
  filter for long lists. Up to five per round.
- **Suggestions with reasons.** Each repository's group says why its skills
  start where they do, for example "You wrote 100% of 20 commits here, so
  this repository can support an anchor", or "You wrote all 8 commits here.
  A repository needs at least 10 commits of yours to support an anchor".
- **The student decides.** Every card can be confirmed at any level. A
  level above the suggestion is saved as the student's own call and shown
  in the skills panel as "from owner/repo, set by you".
- **Large files on request.** Files up to 6 MB are read automatically.
  Larger code files are listed with "Read it anyway" (up to GitHub's 100 MB
  limit); the model still sees at most 45,000 characters of each file.
- **Errors per repository, never all at once:** a private or deleted
  repository, GitHub's rate limit (with the time it resets), a failed
  suggestion with "Try again" for that repository only, and an expired
  connection, which offers Connect GitHub again.

## Skills without overselling

The model proposes; fixed rules decide the suggested level.

- **Taxonomy only.** Skills must be in the skill list, and a skill appears
  at most once.
- **Tools need proof.** A tool (Python, Pandas, Tableau and so on) must
  appear in a dependency file, an import or library line, GitHub's language
  counts or the file types. A mention in the README is not enough.
- **Anchor rule.** A skill can be suggested as an anchor only when:
  - the repository is substantially the student's own: not a fork, at
    least 60% of the commits, and at least 10 commits;
  - its evidence names a code or data file that was actually read. The
    README and dependency files do not count.
- **Caps.** At most 3 anchors and 8 skills per repository. A repository
  with no code or data files read gives basics only.

## Model

GPT-6 Luna is the default. An evaluation on eight of the professor's
public repositories (`docs/development/2026-09-24-repo-skills-eval.md`)
found:
- Luna failed on none of them;
- Luna covered 76% of GPT-6 Sol's applied-or-anchor skills;
- after checking each doubtful suggestion against the code, Luna made no
  plainly wrong suggestion, while Sol made one on both runs.

Luna costs about 2% as much as Sol ($0.02 against $0.43 for the eight
repositories). Gemini 3.8 Flash, the fallback, failed on 2 of the 8.
Students can pick another model in the block.

## Privacy

- The GitHub token stays in the student's browser. The browser reads
  GitHub directly and sends our server only a size-capped summary of each
  chosen repository.
- Nothing about a student's repositories is stored on our server. The
  usage log records the event, model and token counts only.
- Repository text is treated as data: it is fenced in the prompt and
  cannot instruct the model, and the fixed rules above decide levels
  regardless of what a README says.

## Operator notes

- Copy `web/deploy/chatisa-app.zip` to the server as usual (it is a tar;
  extract with 7-Zip or `tar -xf`).
- No server configuration changes. The feature uses the existing GitHub
  OAuth app and the existing OpenAI key (GPT-6 Luna).
- A new per-student rate limit applies to the route
  (`CHATISA_SCOUT_REPO_LIMIT_PER_MINUTE`, default 6 requests a minute).

## Test and gate results

- **Unit:** 1,128 of 1,129 pass. The one failure is the known
  speech-probe timeout under full-suite load, which passes alone. New
  suites, each written failing first:
  - repository summary: caps, notebook stripping, file choice, authorship,
    large files, clipping untrusted input;
  - browser reader: listing, empty repositories, deleted repositories,
    rate limit, expired token;
  - guards;
  - route: a deliberately over-claiming mock model, a README that tries to
    instruct it, malformed bodies;
  - profile storage and labels;
  - the rule text.
- **End to end:** the full suite passes on desktop and at 320 px,
  including the new GitHub skills spec. It covers:
  - picking repositories and raising a level to "set by you";
  - a deleted repository with "Try again";
  - an expired connection, then reconnecting;
  - "Read it anyway" keeping the other repositories' results;
  - focus after confirming;
  - axe A/AA and no sideways scroll at 1280 and 320 px.

  Load-sensitive tests (sandbox statsforecast, Project Assistant exports,
  Interview Mentor keyboard) timed out only under parallel load and pass
  alone. The SQL "Clear" test failed only with a stale development cache
  and passes on this branch and on v6.7.1 with it cleared.
- **Model evaluation:** `docs/development/2026-09-24-repo-skills-eval.md`
  (8 real repositories, GPT-6 Luna against GPT-6 Sol, plus the Gemini
  fallback).
- **Independent review** of the whole branch found no breach of the hard
  rules (token in the browser, nothing stored server-side, levels decided
  by the guards). It found six issues, all fixed with failing-first tests:
  - an expired connection had no way to reconnect;
  - a retry wiped the other repositories' results;
  - a dependency file alone could support an anchor;
  - unclipped fields, and a server error on malformed input;
  - a misleading reason for small repositories;
  - lost focus and unannounced errors.
- **Recorded decision:** a README written to game the model can still
  yield up to 3 anchors, but only in the student's own substantial
  repository and only when citing a real code file.
