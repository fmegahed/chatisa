# ChatISA v6.6.0 Release Notes

**Release Date:** September 23, 2026

---

## Overview

The Portfolio Builder now works for everyone we invite, not only Miami
students, and a showcase can come from anywhere a student learns. This is
project 1 of the four agreed on 2026-09-23 (guests and project origin;
course and skill data; a major-first course picker; reading GitHub).
Design: `docs/superpowers/specs/2026-09-23-guests-and-project-origin-design.md`.

## For guests (invited collaborators outside Miami)

- **Relevant courses (optional).** The career portfolio's Classes step
  becomes up to five typed courses, each a course name and an optional
  school, with **Continue without courses** always available.
- **Their own words on the page.** Typed courses appear under Coursework
  exactly as the guest wrote them ("Applied Regression, Ohio State"),
  each with one sentence on why it matters. A course the model rewords or
  invents is dropped, the same rule the Miami course list already follows.
- **Skipping leaves no trace.** With no courses, the model is told nothing
  about coursework and the page has no Coursework section: no "none
  listed" wording anywhere.
- The review editor lists the typed courses and can restore one that was
  removed or that the model left out.

## For everyone: where did this project come from?

The showcase wizard's first step now asks **Where did this project come
from?**

| Choice | Page header | Repository name |
|---|---|---|
| A Miami course (students' default) | ISA 444 - Business Forecasting | `isa-444-<title>` (as before) |
| A course at another school (guests' default) | as typed, e.g. STAT 4520, Ohio State | `<title>` |
| Self-study | Self-study project | `<title>` |
| A hobby or personal project | Personal project | `<title>` |

Guests never see the Miami option. The README written when the model
returns none follows the origin ("Built for ISA 444.", "A self-study
project."). Miami showcase headers now show the course title next to its
code, matching the career Coursework convention from 6.4.5.

## Nothing that worked before changes

- Drafts, in-progress autosaves and stored sites from before this release
  carry no origin and are read as "A Miami course"; typed courses default
  to none. A republished site keeps its repository name. The only visible
  change to an existing Miami showcase is the course title in its header.
- The generate route accepts payloads from a browser that cached the old
  bundle across the deploy. New text fields are clipped, never rejected.
- Miami students' career flow is unchanged.

## Accessibility

The origin choice is a native radio group whose legend holds the step's
heading. Each origin remembers its own course while the step is open, so a
keyboard user arrowing through the options never loses a pick and typed
text never leaks between origins. Every new input has a visible label. The
new steps pass axe WCAG A/AA at desktop and 320px.

## Test and gate results

- Unit: 947 tests; 945 pass in the full parallel run, and the two
  failures (the known `speech-probe` load timeout and an editor
  indentation test) pass 33/33 in isolation. The portfolio suites add 30
  tests covering origins, outside courses, the route filter, repository
  names, READMEs, and older drafts.
- End to end: the Portfolio Builder and new guest specs pass 31/31 on
  desktop and mobile-320, including axe scans of every new step. The full
  suite (one worker, 25.6 minutes) had 322 passed, 24 skipped, and 1
  failed: the Sandbox "Clear empties SQL console output" test, which runs
  entirely in the browser, touches nothing in this release, and passed 6
  of 7 times in isolation earlier today.
- Hands-on browser check with the mock model, signed in through a guest
  pass, at 320px and 1280px: the origin step and the courses step. It led
  to two polish fixes: placeholder examples appear on the first course
  row only (repeated in grey on later rows, they read as filled-in
  duplicates), and the Project showcase card now reads "One finished
  project, from a course, self-study, or a hobby".
- Typecheck and lint clean.
- An independent whole-change review found one Important issue (typed
  courses could not be restored in the editor) and five Minor ones. The
  Important one and two Minor accessibility findings, re-graded to
  Important, were fixed with tests that failed first. Three Minor items
  are deferred: a Miami course code blanked in the editor renders an empty
  label; typed course text is not fenced in the prompt (it can only affect
  the author's own page); a guest resuming a pre-release showcase
  autosave at the course step loses a Miami course pick.
