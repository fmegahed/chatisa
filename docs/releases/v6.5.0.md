# ChatISA v6.5.0 Release Notes

**Release Date:** September 23, 2026

---

## Overview

A model-catalog refresh for the September 22 launches (GPT-6 Sol and Luna,
Claude Opus 5.5), plus repairs to five open-weight routes that had stopped
serving since v6.3.0. Every id was checked against each provider's live
listing on 2026-09-22 and every HuggingFace route against its per-model
router endpoint; `npm run verify:models` then called all 19 catalog models
for real. Vision claims new to this release were probed with a 64x64
solid-colour image. Every price was re-read from the provider's published
rate.

## Opus 5.5 compatibility: AI SDK upgrade

Opus 5.5 rejects forced tool use. The installed `@ai-sdk/anthropic`
(4.0.18) did not recognise any Opus 5 model id, so for structured output
it fell back to a forced tool call. That worked on Opus 5 but fails on 5.5
with "tool_choice ... not supported for this model", which would have
broken Exam Prep, JobApp Drafter, Job Scout, and Portfolio Builder on
Opus 5.5. `@ai-sdk/anthropic` 4.0.60 knows Opus 5.5 and uses native
structured output for it. Upgrading it pulled in a newer
`@ai-sdk/provider`, so the rest of the AI SDK family moved to its latest
patch releases within the same majors to keep a single provider type
(`ai` 7.0.34 to 7.0.111, `@ai-sdk/openai` 4.0.72, `@ai-sdk/google`
4.0.77, `@ai-sdk/react` 4.0.114, `@ai-sdk/openai-compatible` 3.0.53,
`@ai-sdk/groq` 4.0.46, `@ai-sdk/cohere` 4.0.46).

Verified in the browser against the real models: an Ask Anything
conversation ran Python on Claude Sonnet 5, switched to Opus 5.5 for two
turns (one with a tool call), then switched back to Sonnet 5 with another
tool call. Every answer was numerically correct, with no console errors.

## Route-audit hardening

`npm run models:audit` had not worked since Cohere left the catalog (it
called the Cohere API without a key and exited on HTTP 401). It also
compared HuggingFace ids, which carry a `:provider` suffix, against a
listing without suffixes, and never checked the pinned route itself,
which is the failure that let five routes die unnoticed. It now checks
every HuggingFace entry against its per-model router endpoint and reports
a pinned route as dead, listing the live alternatives.

## Test fixes

- The deep-health e2e test listed an exact set of checks that had not
  included Job Scout's check since v6.1.0. It now requires the known
  checks as a subset, as its own comment intended.
- The exam-resume "discard" e2e test now discards every offered exam. Its
  per-test account persists across runs, and a run interrupted on
  2026-08-21 had left an extra unfinished exam that kept the resume offer
  on screen.

## Test and gate results

- `check-proposed`: every route served and price-matched; the only flag is
  Ternary Bonsai's known lack of structured output.
- `models:audit`: 19 of 19 catalog ids served on their pinned routes.
- `verify:models`: 19/19 chat pass; structured output passes on every
  route that claims it. The five new vision claims (GPT-6 Sol, GPT-6 Luna,
  Opus 5.5, Gemini 3.8 Flash, Qwen3.8 27B on ovhcloud) all identified the
  probe colour.
- Typecheck and lint clean. Unit tests: 918 of 919 pass; the one failure
  is the known `speech-probe` timeout under full-suite load, which passes
  13/13 in isolation.
- e2e (two workers, desktop and mobile-320): 291 passed, 12 failed, 24
  skipped in the full run. On rerun in isolation, the Project Assistant,
  shell, chat, statsforecast and exam specs all pass. Two of the failures
  were the stale tests fixed above. The Sandbox "Clear empties SQL console
  output" test is intermittent (6 of 7 passes); it runs entirely in the
  browser and does not touch model code.
