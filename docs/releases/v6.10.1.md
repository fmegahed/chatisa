# ChatISA v6.10.1 Release Notes

**Release Date:** November 17, 2026

---

## Overview

A model-catalog refresh for the September to November launches (GPT-6.1,
Claude Sonnet 5.5 and Haiku 5.5, Gemini 4), plus repairs to four models that
were failing in the modules that need structured output and the removal of
one that is no longer served at all. Every id was
checked against each provider's live listing on 2026-11-16, every
HuggingFace route was chosen by measurement (speed, structured output,
vision), and `npm run verify:models` called all 25 catalog models for real.
Every price was re-read from the provider's published rate. Also: Next.js
16.4.6 for two critical cache advisories, and the weekly tagger moves to
Gemini 4 Hydrogen after a side-by-side check.

Built on v6.10.0 (the accessibility release), so its bundle carries that
release too. It was prepared as v6.9.4 on a clone that had not yet fetched
v6.10.0, then rebased onto it and renumbered; the overlap was version lines
only.

## Structured output on HuggingFace routes

The app's HuggingFace provider asks for plain JSON mode with the schema
described in the prompt, not enforced. The router's "structured output" flag
describes the enforced mode. MiniMax M3.1 Flash passed 4 of 4 enforced probes
but wrapped its answer in keys of its own ("thought", "analysis") in 8 of 9
attempts on the app's path, so it ships chat only. Enabling enforced schemas
for routes that support them is a possible follow-up; it would need its own
verification across every HuggingFace route.

## Weekly Job Scout tagger

- **The tagger moves to Gemini 4 Hydrogen**, since Gemini 3.8 Flash left the
  catalog. Hydrogen costs twice 3.8 Flash's promotional price, which is also
  what 3.8 Flash would cost from January 1.
- **Hydrogen runs at low thinking.** Before the switch, the new
  `scripts/scout/tagger-model-eval.ts` tagged 60 fresh USAJobs postings with
  the production instructions: 3.8 Flash twice (its run-to-run noise) and
  the candidate once. The September check's 60 stored postings live in the
  production `scout.db`, which this machine does not have.

  | | 3.8 Flash vs itself | vs Hydrogen, default | vs Hydrogen, low |
  |---|---|---|---|
  | Skill-set agreement (Jaccard) | 0.79 to 0.81 | 0.72 | 0.75 |
  | Tagging failures | 0 to 1 of 120 | 3 of 60 | 0 of 60 |
  | False "sponsors" claims | | 0 | 0 |
  | Cost per posting | $0.005 | $0.017 | $0.011 |
  | Seconds per posting | 7.9 to 8.4 | 8.3 | 4.2 |

  At its default level Hydrogen failed the bar set in advance: more failures
  (two were empty responses), extra generic soft skills ("communication",
  "teamwork" on a lifeguard posting) against instructions that say precision
  beats recall, and 3.3 times the cost. At low thinking it passed: no
  failures, agreement close to 3.8 Flash's own, and no sponsorship claim the
  posting did not make. It still lists about one more skill per posting than
  3.8 Flash. "minimal" thinking is refused for this model. Reports:
  `docs/development/2026-11-16-tagger-model-eval.md` and
  `...-thinking-low.md`.
- **The default per-run cost cap rises from $10 to $20.** A full week (up to
  about 1,100 postings) costs about $12 at low thinking, so $10 would have cut
  the last postings of a full week. `CHATISA_SCOUT_MAX_RUN_USD` still
  overrides it.

## Security

`npm audit` reported advisories published since v6.9.1:

- **Next.js 16.3.6 to 16.4.6** (critical: cache poisoning in SSG/ISR
  rendering and a Draft Mode leak through pending `use cache` fills), with
  `eslint-config-next` 16.4.6.
- **zod 4.4.3 to 4.6.7** (memory exhaustion on oversized constrained
  collections), **sharp 0.35.4 to 0.35.5** (librsvg), **source-map-js 1.2.2**.
- Production dependencies now report only KaTeX (4 low), whose fix needs a
  major version of `rehype-katex` and `remark-math`; left for a separate
  change.
- Development tooling still flagged: vitest/`@vitest/mocker`, vite and
  minimatch (test runner, dev server, linter; none ship to the server). On
  this machine npm's resolver crashes while updating them
  (`Cannot read properties of null (reading 'edgesOut')` in arborist's
  peer-set loading), under Node 22 and Node 26 alike: the crash is in the
  globally installed npm 11.5.2. To retry with a newer npm on the next
  tooling pass.

## Compatibility and accuracy

- **AI SDK family to its latest patch releases** (`ai` 7.0.173,
  `@ai-sdk/anthropic` 4.0.105, `@ai-sdk/openai` 4.0.118, `@ai-sdk/google`
  4.0.121, and the rest of the family). `@ai-sdk/anthropic` 4.0.60 did not
  know Sonnet 5.5 or Haiku 5.5; for Sonnet 5.5 it would have forced a tool
  call for structured output, which the model rejects (the same failure
  v6.5.0 prevented for Opus 5.5).
- **Temperature:** Sonnet 5.5 and Haiku 5.5 reject sampling parameters, like
  Opus 5.5, so the catalog omits temperature for them. The GPT-6.x models
  (6.1 Sol, 6.1 Terra, 6 Luna) are reasoning models; the SDK was already
  dropping temperature for them with a warning on every call. The catalog now
  says so, which removes the warning without changing what OpenAI receives.
  Gemini 4 accepts temperature.
- **Vision verified** through the app's own code for all 13 vision claims new
  to this release (64x64 solid-colour probe).

## Tests

- New `pinned-models.test.ts`: every model pinned outside the catalog (the
  weekly tagger, Sandbox completion, module defaults) must exist in it, and
  the tagging cap defaults to $20. Seen failing first against the old
  `tag.ts`.
- The free-model badge test became a rule checked over the whole catalog, as
  no $0 model remains.
- `vitest.config.ts`: the `server-only` alias now uses a forward-slash path.
  On Windows, Vite's resolver turned the backslash path into null, and 41 test
  files failed to load after the repository moved folders.
