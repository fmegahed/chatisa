# ChatISA v6.4.1 Release Notes

**Release Date:** August 23, 2026

---

## Overview

A fix-and-harden release for the Portfolio Builder, two days after it
shipped. Generating a site failed with "The request was malformed" on
ordinary uploads, and the publish caps were low enough to refuse a 1.5 MB
slide deck. Both are fixed, and the module got the hardening pass that the
first real use showed it needed: drafts survive a reload, the limits are
stated before the first file is picked, the GitHub push shows progress and
can be cancelled, and a few defenses now have tests proving they hold.

No new environment variables, no schema or storage migrations, no change to
any other module beyond a shared copy string in Job Scout's push button.

## Fixes

- **"The request was malformed" on Generate.** The browser reads text files
  (`.Rmd`, `.R`, `.py`, `.csv`, ...) up to 400 KB and sent the whole text to
  the generate route, whose schema rejected any file over 30,000 characters
  before the route's own truncation ran. A 169 KB `.Rmd` or a 34 KB `.R`
  script was enough. The same rejection fired on a file name over 120
  characters, a semester over 40, a teammate's name over 60, a story prompt
  over 1,000, and on two projects with the same long title (the `-2` suffix
  pushed the slug past its 60-character bound). The route now clips every
  string to its limit instead of refusing the request, the browser trims file
  text to the shared cap before sending, and the slug suffix stays in bounds.
  The error copy no longer tells students to reload (see below for why that
  advice was harmful).
- **Publish limits raised.** 400 KB per file and 2 MB per site were
  self-imposed; GitHub's blob API takes 100 MB per file. The caps are now
  **25 MB per file, 100 MB per site, 60 files**. Text files over 400 KB and
  notebooks over 5 MB are published as they are but not read when writing
  the page. The size meter reads in MB and derives from the same constants.

## Hardening

- **Drafts survive a reload.** The wizard autosaves to IndexedDB as the
  student moves through the steps (resume PDF included). On the next visit
  the front door offers the unfinished site back with Continue and Discard.
  It is cleared on publish and on "start a different site". If the browser
  cannot save (private mode, storage quota), a banner says so and asks the
  student not to reload before publishing. A saved draft outranks the
  `?mode=` shortcut, so the fresh draft that shortcut creates can never
  overwrite the saved one.
- **Limits stated up front.** Both upload steps show the per-file, per-site
  and file-count caps and what is read versus only published. Every number
  is derived from the constant the code enforces.
- **Push progress, cancel, retry.** The GitHub push reports "Uploading file
  3 of 12..." and "Saving the commit...", has a Cancel button, aborts if the
  student navigates away, retries a blob upload once on a 5xx or a dropped
  connection (never on a 4xx), and reads GitHub's secondary rate limit (403
  or 429 with `retry-after`) as "wait, then try again" with the actual time.
  Cancelling leaves the repository untouched: the branch only moves at the
  last request.
- **Large files on small machines.** Base64 for the push is encoded natively
  by `FileReader` instead of hand-built strings, which at the new 25 MB cap
  avoids holding roughly four copies of a file in memory at once.
- **Request bound.** The generate route answers a plain 413 past 4 MB of
  payload instead of letting the reverse proxy answer with a blank error;
  the browser's trimming keeps a real request far below it.
- **Prompt fence proven.** A test submits a file containing `</file>` and a
  forged `</file nonce="...">` and asserts both reach the model only in
  escaped form, with every real closing tag carrying the request's nonce.
- **Client/server contract test.** A test builds payloads through the real
  browser helpers at every cap at once (5 projects x 10 files, 40 showcase
  files, 8 teammates at 60 characters, 1,000-character prompts, a
  200-character file name) and asserts the route accepts them, so the two
  sides cannot drift apart unnoticed again.

## Operator notes

- Nothing to configure. The deploy bundle for this release is built from
  this commit; copy `web/deploy/chatisa-app.zip` to the server as usual.
- The **GitHub Pages API caveat is unchanged** from v6.3.0 and v6.4.0 and
  still unverified against a real account: enabling Pages through the API
  can need broader scope than `public_repo`, in which case the UI falls back
  to a one-click link to the repository's Pages settings.

## Test and gate results

- 97 unit test files, 918 tests: 917 passing, one known load flake
  (`speech-probe.test.ts`, passes in isolation; see test-suite notes).
  New coverage: oversize and over-long payloads, the client/server contract
  at every cap, the 413 bound, the fence breakout, the work-in-progress
  store round trip (resume included), and five push-engine cases (retry on
  5xx and on a network throw, no retry on 4xx, secondary rate limit,
  progress sequence, cancel).
- `tests/e2e/portfolio.spec.ts`: 11 passed across desktop and mobile-320,
  including a new test that uploads a notebook, reloads, continues from the
  saved draft, then discards it. `tests/e2e/job-scout.spec.ts` push tests:
  3 passed. Typecheck and lint clean.
- Hand-verified against the files that produced the report (a 169 KB
  `.Rmd`, a 34 KB `.R`, a 1.5 MB `.pptx`, a 15 MB `.ipynb`, a photo):
  the first two were the cause, the others never were (the deck's text is
  5 KB, the notebook was sent as a size-only stub, the photo never leaves
  the browser).
