# ChatISA v6.10.0 Release Notes

**Release Date:** October 2, 2026

---

## Overview

Miami University's accessibility office tested ChatISA in September 2026
and sent two reports: an automated scan (Accessibility Shield, 20 rows) and
a screen reader usability review (JAWS and NVDA, 19 findings), both against
WCAG 2.1 AA and Section 508. After merging the three findings that appear in
both, that is 36 issues, filed as GitHub issues #4 to #39 with tracking issue
#41. This release fixes 35 of them. The remaining one (#10) needs testing
with a screen reader to confirm its cause; see "Still open" below.

The fixes also cover places in the app with the same problems that the
reports did not list, and a new site-wide test now checks every module for
these problem types, so they stay fixed.

## Across the app

- **Placeholder text is readable.** It measured 3.7:1 (3.3:1 in the Coding
  Studio assistant). It now uses the brand dark tan: 4.6:1 to 5.5:1 on the
  light surfaces, and at least 6:1 on Coding Studio's dark theme (#7, #8).
- **Changes are announced.** One app-wide announcer reports outcomes such
  as "Saved", "Added to the team" and "12 jobs match your filters" to screen
  readers, so a module no longer has to put its own live region in each
  place.
- **Required fields are marked.** A red asterisk, the field's `required`
  attribute (which screen readers announce), and a short note saying what
  the asterisk means (#25, #31).
- **No empty or invisible tab stops.** Code samples and tables are tab
  stops only while they actually scroll; text-only boxes are no longer tab
  stops at all (#19).
- **Page titles.** Project and coach pages are titled with the project and
  course (#28). Titles are now in the page as it first loads, rather than
  added a moment later, and the "page not found" page has its own title.

## Chat (Coding Tutor, Ask Anything, Project coaches)

- "You" and "ChatISA" are second-level headings, and a reply's own
  headings start one level below them, so the outline no longer skips levels
  (#4). Replies look the same as before.
- When a reply finishes, the status line says "ChatISA finished responding."
  (or "Response stopped."). In Ask Anything it waits until the assistant's
  last tool step is done (#5).
- The invisible "Choose files to attach" control next to Attach file is
  gone; the visible button is the only one (#6).
- "Output" and "Error" under runnable code are headings, so a screen reader
  user can jump from long code to its result (#9).

## Coding Studio

- **Zoom and narrow windows.** Below 1024 px wide (which includes 400% zoom
  on a laptop), the panes stack in one column and the page scrolls only
  vertically (#15).
- **Keyboard.** The SQL / Python / R choice is a proper radio group: arrow
  keys move between languages, and choosing one no longer sends focus to
  the console (#17, #18). The editor tabs and the Plots / Help tabs have one
  tab stop each with arrow keys (#20). The pane dividers are named,
  keyboard-resizable splitters ("Resize Script and Console") rather than
  empty stops (#16).
- **Screen readers.** Panes are named regions (#11, #12). Each run's output
  sits under an "Output of run N" heading (#22).
- **Line numbers.** A small "Ln X, Col Y" line under the editor follows the
  caret, and Alt+Shift+L (Option+Shift+L on a Mac) reads out the line,
  column, and any problem flagged on that line (#21). The shortcut is listed
  in the keyboard shortcuts dialog.
- **Contrast.** Line numbers are at least 5.7:1 (they were 3.7:1); three
  syntax colours that fell below 4.5:1 were darkened; in the dark theme, red
  text and the focus ring use a lighter red that is at least 6.2:1 (#13). A
  side effect: R code in the light theme had shown keywords, strings and
  comments uncoloured, and now has its colours.
- **Scrolling.** The script area can be scrolled by keyboard (#14).
- **Plots.** Alt text now describes the chart instead of "Plot 1": its type,
  title, axes and legend, read from the matplotlib figure in Python or from
  the plotting code in R and SQL. A "Describe this plot" button shows the
  same details as text. This also applies to plots in Coding Tutor and Ask
  Anything (#23). Fully navigable, sonified plots with MAIDR are planned
  for a later 6.x release (#40).

## Exam Prep

- After you submit an answer, focus moves to the feedback; after Next, to
  the new question; at the end, to the results (#24).

## Project Assistant

- Add teammate says up front that it needs a @miamioh.edu address, shows
  errors next to the field, announces when someone is added, and stays
  usable while it works, so a screen reader no longer reports the button as
  "unavailable" (#26, #27).
- The "What does adding a teammate do?" explanation now appears right
  after its button, before the email field it explains (#29).
- Coaching worksheets have section headings that match the Word download
  (#30).

## Portfolio Builder

- Required fields are marked, and when Next is unavailable the step says
  what it is waiting for (#31).
- "Continue unfinished portfolio" and "Discard unfinished portfolio" say
  what they act on (#32).
- Moving between steps puts focus on the new step's heading (#33).
- List buttons name their item ("Remove project 2", "Remove model.R").

## Job Scout

- Each job card's buttons name the job, for example "Save Data Analyst at
  Queen City Insurance", while the visible text stays short (#34).
- **Visible change:** Save is now a toggle. When a job is saved, the
  button keeps the word "Save" and shows a check mark on a shaded chip
  (previously the text changed to "Unsave"). Screen readers hear "Save ...,
  pressed" (#35).
- Hiding a job is announced and focus moves to the next job (#35). Hidden
  jobs can come back: "Undo" right after hiding, and "Show hidden jobs (n)"
  lists them with Unhide on each (#39).
- Changing a filter announces how many jobs match (#36).
- Majors, co-majors, minors and each skill group are grouped with a label
  that screen readers read (#37).
- Saving your profile moves focus to the jobs list (#38).
- **Bug fix found while testing:** on a device that had never saved or
  hidden a job, the first Hide left the job on screen until the page was
  reloaded.

## Still open

- **#10, NVDA with Firefox reads the first character of each code line as
  blank.** No cause was found in ChatISA's editor setup; the likely cause is
  in the CodeMirror editor library itself. The issue lists a short test to
  run with NVDA before reporting it to CodeMirror. Until then, the new
  Alt+Shift+L shortcut reads the current line's position, and copy and run
  are unaffected.
- **#40, MAIDR plots.** Planned for a later 6.x release.

## Test and gate results

- Type check and lint clean.
- Unit: 124 files, 1,184 tests pass. New: heading demotion, plot
  descriptions, caret helpers, project titles and invite rule, and the
  first-hide regression.
- End to end: the full suite passes at desktop and at 320 px. New: a
  site-wide accessibility sweep (axe at WCAG 2.1 AA on every module, plus
  checks for problems axe does not test: empty and invisible tab stops,
  labels on unlabeled elements, placeholder contrast, unmarked required
  fields, page titles), and behaviour tests for every issue above.
- Rendered pages checked in a browser: Coding Studio in both themes at
  desktop and 320 px, a Coding Tutor run, and the new-project form.
- Not run: real screen readers (NVDA, JAWS). Worth a pass by the
  accessibility office on the items they reported.
